# ATLAS OF LOOKING｜观看图鉴

独立艺术研究档案网站。米白、深灰与酒红，中文宋体与英文衬线字体；响应式页面、舒适长文阅读与可持续编目的内容结构。

## 立即运行

需要 Node.js 22.12+（建议 24 LTS）与 npm。仓库已锁定依赖。

```sh
npm ci
npm run dev
```

未配置 Supabase 时为**只读本地预览**：完整显示上传包中的 13 份研究整理稿，所有信息标记待核实。它不模拟管理员身份，也不把本地修改冒充云端保存。正式部署必须配置 Supabase。

```sh
npm test                 # 数据、PostgreSQL RLS、备份完整性与恢复测试
npm run build            # TypeScript + 生产构建
npm run test:e2e         # 桌面与手机 Chromium 交互
```

浏览器测试默认使用 `/usr/bin/chromium`；本机可通过 `CHROMIUM_PATH` 指定 Chromium 可执行文件。

## 内容与功能

- 艺术家、作品、主题研究、个人札记、参考文献共五种独立档案，交叉关联通过 ID 建立。
- 艺术家索引全文搜索、关键词过滤、排序、图版／列表切换；六个内容入口及参考来源索引。
- 管理员创建、编辑、删除、保存草稿、公开发布、图片上传、JSON 批量导入／导出。
- 访客仅能读取已发布内容。普通登录用户没有编辑权，也不能自行成为管理员。
- 图片为私有 Storage 对象；仅管理员或已发布档案的图片允许获取访问链接。本站签发链接有效期 10 分钟，撤回发布不撤销已签发链接；曾公开的图片不应再视为秘密。
- 数据库自动记录新增、更新、删除的完整快照；编辑采用时间戳检查避免覆盖其他会话的修改。
- JSON 导入为原子事务，默认不覆盖 ID，全部存为草稿；显式覆盖须先下载备份并核对版本。
- 字体在构建时本地打包，无需外部字体或脚本 CDN。

## 原始资料

`data/original-archives.json` 为上传包档案的原样副本。`data/archives.seed.json` 是可迁移的 v1 导入文件：正文、简介、名称、生卒年、关键词和原始链接均保留，增加类型、核实说明、状态与关联字段。日期字段记录本次迁入日期，不是原研究的创作日期。

13 份：白南准、陈界仁、毛里齐奥·卡特兰、杰曼·克鲁尔、刘炜、蒋志、乌尔斯·费舍尔、朱利安·施纳贝尔、格奥尔格·巴塞利兹、安塞尔姆·基弗、约尔格·伊门多夫、迈克尔·沃尔夫、泰伦·西蒙。

未经独立核实的资料均保持 `pending`，未补造事实或参考文献。原稿中的代表作品与分析仍在正文内完整保留；作品入口自动提取《书名号》内的文字，明确作为“原稿中的作品线索”，其中可能含摄影书或系列名称，不能视为已编目的独立作品记录。管理员可逐步整理成结构化作品档案。

附件未提供作品图片文件或使用许可；几何索引图均标注“非作品图像”。编辑关联根据原稿中的研究方向建立，不构成艺术史关系的事实断言。原稿提及但没有独立档案的杜尚、索菲·卡尔等对象未虚构补齐。

## 接通云端并部署

按 [部署步骤](docs/deployment.md) 创建 Supabase、导入 SQL、设置管理员，随后在 Vercel 连接本 GitHub 仓库。所有访问控制均由 PostgreSQL RLS 执行，不能靠隐藏按钮代替权限。

- [数据库迁移](supabase/migrations/001_archive.sql)
- [数据格式与未来 AI/API 接入](docs/data-format.md)
- [完整备份与恢复](docs/backup.md)
- [验证记录与待完成事项](docs/validation.md)

**不要把 service_role、数据库密码、Vercel Token 或管理员密码写入 `VITE_*`、源码、聊天或公开网站。** 浏览器仅使用 Supabase URL 与 publishable/anon key。个人备份工具在本机读取安全注入的管理员凭据，不需要浏览器持有私密密钥。
